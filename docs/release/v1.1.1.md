# diag-lang v1.1.1: Escape invisible characters

**Patch.** The renderer now escapes characters that render as nothing, so a diagnostic about a name that hides one shows the difference. No public item changes.

## What is diag-lang?

Compiler-style diagnostics: errors, warnings and notes with labelled spans, rendered as source frames with carets, with error codes, fix-it suggestions, JSON output and a capped collector.

## Security

The renderer already escaped C0 and C1 controls, `DEL`, carriage returns, the line and paragraph separators and the bidi controls, so untrusted text could not drive a terminal or reorder a line. It printed invisible characters raw. ZERO WIDTH JOINER is a valid identifier character under UAX #31, so `admin\u{200d}` and `admin` are two different names that look the same, and a diagnostic such as "duplicate definition" printed both the same way.

Every default-ignorable code point is now written as a visible `\u{..}` escape: the zero-width space and joiners, the word joiner, the byte order mark, the Hangul fillers (U+115F, U+1160, U+3164, U+FFA0), variation selectors, the tag characters U+E0000 to U+E0FFF, SOFT HYPHEN and the rest of the set. That applies to source lines, messages, labels, notes, help, suggestions and file names. Caret columns account for the escape, so underlines stay aligned.

```text
error: unused variable `admin\u{200d}`
 --> spoof.rs:1:5
  |
1 | let admin\u{200d} = 1;
  |     ^^^^^ here
```

Emoji sequences that use ZERO WIDTH JOINER or a variation selector also show the escape now. That is the cost of making hidden characters visible.

## Changed

- Depends on `unicode-lang` 1.1, which provides the `Default_Ignorable_Code_Point` table. No new third-party dependencies.

## Compatibility

No public API change. Output changes only for text that contains invisible characters. MSRV stays at Rust 1.85.
