# diag-lang v1.0.1 — end-of-input frames, safe text, linear multi-line rendering

**Patch release.** No public API changes. Five fixes from the LexerSketch issue
ledger: end-of-input errors render with their source frame (H04), control
characters from untrusted text are escaped (M15), multi-line rendering is linear and
long spans are elided (M16), no line index is rebuilt per frame (M17), and carets
align under wide and combining characters (M18).

## What is diag-lang?

The diagnostics layer of a compiler front-end. It collects diagnostics — a
severity, a message, and labelled spans — and renders them with source context, a
caret underlining exactly where the problem is. Positions come from `span-lang`,
source text from `source-lang`.

## Fixed

### End-of-input errors keep their frame (H04)

lang-forge (and any parser) reports "found end of input" at `Span::empty(len)`. That
used to render as `span N..N is outside the loaded sources`. Now:

```text
error: expected `"`, found end of input
 --> broken.lsf:3:17
  |
3 | stmt = "expr ';'
  |                 ^ expected `"`
  |
```

The caret sits just after the last visible character of the last line: for a text
ending in a line break, before that break; without one, after the final character;
for an empty source, at `1:1`. The frame's `--> file:line:col` header names exactly
the caret's line and column, so the two never disagree (tested over eight input
shapes and by a property). This covers every position source-lang 1.0.1 attributes
to the source: a single-source map (lang-forge's case) and the most recently added
source. **Known limitation:** one exception, from source-lang's contiguous 1.x layout: the end of a source that
is not the last one is the same position as the next source's first byte, so an
end-of-input label there renders at the next source's `1:1` (fixed by
source-lang 2.0's reserved end positions); a test pins it.

### Wide and combining characters align (M18)

Carets are placed in Unicode display width (`unicode-lang::char_width`): CJK and
wide emoji take two columns, combining marks none; tab stops count display columns.

```text
1 | let 名前 = 値;
  |            ^^ wide
```

## Security

### Control characters are escaped (M15)

Source lines, the message, labels, notes, help, and file names are written with C0
and C1 controls (including `ESC`), `DEL`, carriage returns, U+2028/U+2029, and the
bidi override/isolate/mark controls escaped as `\u{..}`. No ANSI or OSC sequence
from untrusted input can reach a terminal; the only escapes in the output are the
renderer's own colours. Tabs are kept; newlines are kept in messages, notes, and
help, and escaped in file names.

## Changed

### Linear multi-line rendering with elision (M16, M17)

A span over more than five lines shows its first two and last two lines with a
`...` line between (spans of up to five lines render exactly as in 1.0.0). Marks
are grouped by line in one sorted pass and frames by file in one pass. No line index
is built per frame: line numbers come from source-lang 1.0.1's cached line table,
and line boundaries from a scan outward from each label, so a frame costs what it
prints plus `O(log lines)` per label.

## Benchmarks

Criterion, Windows x86_64, Rust 1.95, release profile. "Before" is the `v1.0.0`
tag's code (against source-lang 1.0.0 from crates.io) with the new bench file;
"after" uses source-lang 1.0.1 from the local path. Old and new were run back to
back; the machine was shared with another build session.

| Benchmark | v1.0.0 | v1.0.1 |
|---|---|---|
| `render_whole_file/50k_lines` (one label over a whole 50,000-line, 1.9 MB file) | 1.2042 s | 1.6903 µs |
| `render` (one-line label, 3-line file) | 963.76 ns | 765.22 ns |
| `construct` | 61.799 ns | 67.188 ns |

The whole-file case also prints 4 source lines instead of 50,000 (elision); the
time difference is mostly the removed per-frame line index and the removed
quadratic per-line mark filter.

## Dependencies

- `source-lang` requirement raised from `"1"` to `"1.0.1"` (end-of-input
  resolution for the last source and the cached line table are 1.0.1 behaviour). **Publish
  source-lang 1.0.1 first**; until then this crate does not resolve standalone.
- New: `unicode-lang = "1"` (`default-features = false`, `no_std` kept), a
  first-party `-lang` crate with zero dependencies, for display width.

## Breaking changes

**None in the API.** Rendered output changes where the fixes require it: long spans
are elided, end-of-input labels get a frame, control characters are escaped, and
wide characters shift carets. The exact bytes of a frame beyond the documented
layout rules are not part of the 1.0 contract.

## Verification

1.0.1 supplied locally via

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings                      # also +1.99
cargo clippy --all-targets --all-features -- -D warnings       # also +1.99
cargo clippy --all-targets --no-default-features -- -D warnings # also +1.99
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.85 clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
```

All green. Counts (all features): 18 unit + 20 single-line snapshot + 13 frame
snapshot + 4 colour + 8 property + 24 doctests. Property tests were also run at
20,000 cases each.
